# E2E-тесты (Playwright)

End-to-end тесты для примера **ContractApproval** на платформе BaSYS.

## Требования

- Node.js 18+ (проверено на v20).
- Запущенный стенд BaSYS (по умолчанию `https://localhost:44365`).

## Установка

Из папки `tests/`:

```bash
npm install
npx playwright install chromium
```

## Настройка секретов

Реальные учётные данные хранятся только локально в `tests/.env` и **не коммитятся** в репозиторий (см. `tests/.gitignore`).

Скопируйте шаблон и заполните значения:

```bash
copy .env.example .env   # Windows (PowerShell/CMD)
# или
cp .env.example .env      # bash
```

Переменные:

| Переменная | Назначение |
|------------|------------|
| `BASYS_BASE_URL` | Базовый адрес стенда (например `https://localhost:44365`) |
| `BASYS_EMAIL` | Email пользователя |
| `BASYS_PASSWORD` | Пароль |
| `BASYS_DB_NAME` | Имя базы данных |

## Запуск

```bash
npm test            # прогнать все тесты (headless)
npm run test:headed # с видимым браузером
npm run test:ui     # интерактивный UI-режим Playwright
npm run report      # открыть HTML-отчёт последнего прогона
```

## Как это устроено

- `playwright.config.ts` — конфигурация: `baseURL`, игнор самоподписанного HTTPS-сертификата, два проекта.
- `src/config.ts` — чтение `.env`, сборка URL приложения (SPA hash-роутинг: `/app#/...`).
- `e2e/auth.setup.ts` — проект `setup`: логинится через форму и сохраняет сессию в `.auth/state.json`. Остальные тесты переиспользуют её и не логинятся заново.
- `e2e/person-create.spec.ts` — пример: открывает справочник `person`, добавляет запись, проверяет автоформирование поля «Заголовок» из ФИО и сохраняет.

## Примечание

Тесты рассчитаны на русскую локаль интерфейса (метки кнопок «Добавить», «Сохранить и закрыть»). При другой локали поправьте тексты в тестах.
